# 위블록 WeBlock — 1호 자산 3D 스크롤 랜딩

부동산 조각투자 플랫폼 위블록의 1호 자산 **설악가평IC 드라이브스루**(2023년 준공·운영 중) 랜딩.
스크롤하면 실사 사진이 보라 빛에 훑히며 레고 블록 건물로 바뀌고,
해체 → 조각화 → 투자 → 실적 → 배당 → CTA 로 이어지는 8챕터 스토리텔링이다.

- 라이브: https://web-lego-landing.vercel.app/
- 빌드 스텝 없는 정적 사이트. three.js r0.185 를 `vendor/` 에 로컬 벤더링, 외부 CDN 무의존.
- 기획·카피·수치 근거는 [PLAN.md](./PLAN.md).

## 반드시 지킬 것

1. 이 자산은 **이미 준공·운영 중**이다. "우리가 짓는다" 서사 금지.
2. 임차인은 항상 **"글로벌 커피 프랜차이즈"**. 특정 브랜드 상표·로고 사용 금지.
3. 수치는 **2026.05 투자제안서** 기준. 07 챕터 하단 면책 문구 유지.
4. 모바일은 **위 = 건물 / 아래 = 글과 그래프** 분할을 깨지 않는다. 데스크톱은 같은 원리로 좌우를 나눈다.

## 실행

```bash
python3 -m http.server 8123     # 저장소 루트에서
# → http://localhost:8123
```

ES 모듈을 쓰므로 `file://` 로 직접 열면 안 된다(정적 서버면 무엇이든 OK).
파일 하나로 보내야 할 때는 단일 HTML 번들을 쓴다 → [배포](#배포).

## 건드리기 전에 — 이유가 있어서 이렇게 된 것들

- **T 는 전체 스크롤 길이를 8등분한다** (`measure()`). 섹션 높이로 재면 챕터 경계마다 T 가 멈춰 3D 가 얼어붙는다.
- **`.pin` 은 `position: fixed`** (sticky 아님). sticky 로 되돌리면 챕터 사이에 카피 없는 검은 화면이 생긴다.
- **카피 교차 페이드 `FADE`** 는 `l = T − i` 이고 음수 구간을 허용해 앞뒤가 겹친다. 이웃한 챕터는 반드시 다른 레인이어야 잔상이 겹쳐 읽히지 않는다(01·02 만 예외라 `FADE[1]` 을 앞당겨 끊었다).
- **카메라는 키프레임 + 실제 투영 역산.** `building.mass`(건물 정면 실루엣 상자)를 화면에 투영해 좌우 잘림 방지 거리와 서막 프레이밍 밴드를 푼다.
- **서막 실사 사진은 매 프레임 그 투영 사각형에 맞춰 앉는다** (`fitHeroPhoto`). CSS 로 위치를 고정하지 말 것 — 사진과 레고가 같은 자리에 서는 근거다. 매싱을 고치면 사진도 따라온다.
- **매싱의 가로 배치는 실사 사진에서 잰 값이다.** 2F·3F 캔틸레버 슬래브, 3F 상자·지붕의 좌우 끝은 사진과 ±5px, 우드 기둥(1·2층 19..25 / 3층 16..25)과 1층 앞줄 필로티는 ±10px 안에서 겹친다. 그리드를 옮기거나 넓히면 [검수](#검수)의 정합 측정을 다시 할 것. 우드 기둥은 유리·슬래브보다 나중에 채워야 앞면이 우드로 남는다.
- **치환 경계선 `--edge`/`--soft`(px)** 는 JS 가 준다. 건물 구간에 시간을 몰아준다.
- **데스크톱 좌우 분할**: `LANE`(챕터별 카피 레인)에 따라 거리 역산이 끝난 *뒤* `setViewOffset` 의 x 로 화면만 민다. 서막·CTA 는 0.
- **디텐트(딸깍)**: `scrollToT()` 가 챕터마다 비트(`BEAT`) 부근에서 기울기를 낮춘다. `__seek()` 은 그 역함수(`unwarpLocal`)를 써야 한다 — 빼먹으면 검수가 통째로 어긋난다. 기울기를 0 으로 두면 3D 가 얼어붙으니 `DD < 1` 유지.
- **그림자 맵은 `autoUpdate = false`**. 조립(prog)·조각화(shatter)가 움직일 때만 다시 그린다. 그림자를 드리우는 물체를 새로 추가하면 이 판정도 같이 손봐야 한다.
- **`uiUpdate()` 는 T·rawT 가 멈추면 통째로 건너뛴다.** 화면 값은 전부 T 의 함수여야 한다(시간 기반 DOM 애니메이션을 여기 넣지 말 것).

## 검수

`python3 -m http.server` 로 띄우고 playwright-core + SwiftShader 로 촬영한다.

- `?snap` 으로 열면 스무딩 없이 즉시 시킹하고 넛지·스냅이 꺼진다.
- `window.__seek(T)` 로 시점 고정, `__info()` / `__probe()` 로 T·fps·건물 화면 점유율(bx, by)·분할 상태(lane, off) 확인.
- **SwiftShader 에서 이 씬은 1fps 미만이다.** 시킹 후 시간으로 기다리지 말고 rAF 를 3번 기다린 뒤 읽을 것 — 안 그러면 한 시점씩 밀린 값이 나온다. 프레임을 기다리지 않고 지금 상태를 읽으려면 `__rawNow()`(스크롤 위치 기준 T) · `__snapBusy()`.
- `__ready` 대기 60s, screenshot timeout 180s.
- 모바일 **390×844** 와 데스크톱 **1600×1000** 둘 다 본다. 데스크톱은 1280×800 · 1024×700 도 가끔.
- **실사 정합**: T=0 에서 카피·UI 를 숨기고 같은 프레임을 사진 있음/숨김으로 두 번 찍어, 밝은 슬래브 행의 좌우 끝을 비교한다.

playwright-core 는 저장소에 넣지 않는다(`.gitignore`). 필요할 때 `npm install playwright-core --no-save`.

## 배포

- **Vercel 은 `wex-corporation/web-landing-2608` 의 `main` 을 배포한다.** 개발은 미러인 `felix-seoul/web-landing-2608` 에서 하고 있어서, felix 에 병합한 뒤 wex `main` 으로 fast-forward 동기화해야 라이브에 반영된다. Vercel 프로젝트의 Git 연결을 felix 쪽으로 바꾸면 이 단계가 없어진다.
- 별도 빌드 설정은 없다(Framework: Other, 저장소 루트를 그대로 서빙, `vercel.json` 없음).
- **단일 HTML 번들**: `node tools/build-single.mjs` → `dist/weblock-landing.html` (텔레그램·메일 전송용, `file://` 에서 열린다). 소스를 고치면 다시 빌드해 함께 커밋한다.
  ⚠ `build-single.mjs` 의 `.replace()` 치환값은 반드시 **함수**여야 한다. 문자열로 두면 three.js 안의 `$&` 가 치환돼 소스가 깨진다.
